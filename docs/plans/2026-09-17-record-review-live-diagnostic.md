   material facts, despite omission of its final decision. One is a complete,

under-specified. Mixed grounding/retention tuple vocabularies and many independent
facets increase operational burden. Candidate-relative retention wording may

hypotheses, not proven explanations of the model's internal behavior.

## Provider identity caveat discovered after collection

DeepSeek's [current official documentation](https://api-docs.deepseek.com/),
checked September 17, says `deepseek-v4-flash` and
`deepseek-v4-flash-vision-exp` are retired names whose calls are served by
DeepSeek-V4.1-Flash; the current public name is `deepseek-flash`.

This campaign verifiably **requested** `deepseek-v4-flash`; that string is not an
immutable serving-model identity. The collector did not retain response model
or system fingerprint, so it cannot independently establish the underlying
revision of each call. Current provider documentation is not evidence of the
precise backend used by each historical campaign, nor proof that rerouting
caused these semantic failures. Historical comparisons must not silently assume
the same request name means unchanged weights. New experiments should explicitly
record requested identity, reported identity/fingerprint where supplied, model
mode, observation time and the limits of provider attestation.
