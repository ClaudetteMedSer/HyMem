# Record-oriented review — offline repair plan

## Scope

The completed source-review Stage A diagnostic passed execution and accounting
but repeatedly accepted a speaker reversal and an invented display name, and
rejected a justified bounded exclusivity claim. The user approved continuing
with offline repair. No new provider calls, transfers, credentials, production
stores, deployment, restarts or full LME are included.

Preserve the failed source-review implementation, its scorer, frozen fixtures,
gold, requests and paid responses. Develop an additive diagnostic in
`benchmarks/digest_record_review.py`. Reuse the existing strict projection,
binding and response-authority validators; do not weaken runtime safeguards or
introduce keyword-specific acceptance rules. Model judgments remain diagnostic,
never semantic proof or publication authorization.

## Sequential implementation and root verification

1. A new agent colocates each canonical text with its exact current-message
   attribution and associated boundary text with its own actual-message
   attribution. Separate actor-attribution checks from the broad relations
   judgment. Root verifies role swaps, cross-message boundaries, same-message
   continuations, scope isolation, tamper rejection, caps and call scheduling
   before accepting this step.
2. Only after that gate, a fresh agent makes peer/workspace identifiers explicitly
   typed opaque metadata and gives identity assertions their own checks. No
   metadata-derived display names, inferred identities or additional primary
   evidence are created. Root verifies null/empty/Unicode identifiers, genuine
   canonical names, false name claims and authority-plane attacks.
3. Only after the identity gate, a fresh agent separates quantified/bounded-scope
   judgments and distinguishes explicitly closed sets from open-world claims.
   Root verifies both supported bounded and unsupported global forms, with
   symmetric positive/negative cases. Preserve assertion, residual relations,
   outcome and source-owned retention obligations rather than dropping hard
   checks to make acceptance easier.
4. Expand offline controls with renamed and structurally varied examples, then
   run combined regression and preparation checks. Verify all 488 pre-existing
   Python/SQL files against their frozen hashes. Report call/check/input-size
   changes and limitations; do not silently reuse old relations labels for new
   facet-level semantic targets or rescore old paid replies.

## Acceptance limits

Offline tests establish data preservation, explicit obligations, strict parsing,
accounting and integration behavior with scripted replies. They cannot show that
DeepSeek now resolves actors, identities or quantifiers correctly. Preserve the
observed failures as development evidence. A later live evaluation requires new
frozen labels, untouched paired controls and fresh approval; no automatic paid
test follows this work.

independent reviewer endorsed all nine new target-labelled pairs after checking
each source/candidate/annotation. The subsequent quantified-scope step is below.

Quantified-scope gate accepted after a third implementation agent and root
review: **324 record-review tests passed**, including 69 scope implementation
tests, 25 independent scope attacks and all 22 development-fixture tests. Every
original relations field now retains four mandatory facets: actor attribution,
identity, quantified scope and residual relations. Original assertions, outcomes
and source-owned retention checks remain mandatory. Acceptance of one facet
cannot override another facet's veto.

The fixed scope rubric distinguishes a closed bounded domain from an unsupported
broader claim, and preserves polarity, cardinality, exclusions and uncertainty.
It is also reflected in title/assertion instructions so those checks do not
contradict the bounded-entailment policy. Root review required two refinements:
deduplicate the rubric into one bound definition per request; and allow
unambiguous full-candidate anaphora without silently narrowing an explicitly
global or contradictory claim. Rehashed changes to definitions, references or
obligations are rejected before any invocation. No lexical classifier assigns
semantic verdicts, and parsing still never grants publication authority.

The final 1,719-test gate includes all earlier stages. Failing intermediate
receipts remain alongside the accepted ones; they are not reported as passes.
