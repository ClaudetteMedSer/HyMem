# Retention diagnostic: repair the evaluation contract first

Latest continuation: [summary coverage-owner correction](2026-09-18-summary-retention-scope.md).
A subsequent audit found that per-item supporting citations are not exhaustive
retention scopes. The historical per-item diagnostic is not eligible for general
runtime promotion; its frozen results below remain unchanged.

## Why this follows the live pilot

The [64-call pilot](2026-09-18-retention-inventory-live-pilot.md) failed. Its
collection infrastructure worked, but independently reviewed replies exposed
source-inventory and matching errors. Review also found a defect in our controls:
some procedure prerequisites were encoded only as retrieval `triggers`.

Fixing those labels by redefining production triggers would be wrong. The frozen
run remains immutable failed evidence. Its scores against the original labels
are not validated semantic accuracy for the affected cases.

## Sequential repair and root verification

1. **Field-role and fixture correction (v2).** A separate implementation agent
   changes only the offline candidate version and matching instructions, plus
   adds new fixture/test files. Prerequisites belong in actual assertions, not
   query hints. Preserve explicit conditions that can legitimately occur in
   an imperative name; do not invent a blanket title exclusion.
   The twelve original fixtures stay unchanged. Fourteen versioned replacements
   comprise corrected copies plus a two-case trigger-only countercontrol.
   All descriptions are valid nonempty strings. Source bytes, attribution,
   coordinate anchors and source-side gold stay intact.
   Root separately reviews the diff and validates each procedure through the
   actual runtime shape validator, candidate-blindness, declared mutations,
   label isolation and the unchanged uncertainty/rejection gate.
2. **Semantic-inventory correction (v3, verified offline).** After the first fix
   passes verification, a different agent may refine the offline instructions
   to represent complete contextual events, distinguish material requirements
   from incidental details, and retain each actual action-order relation.
   Matching must tolerate genuine paraphrases without forgiving changed actors,
   duration, polarity or prerequisites. No fixture names, keyword heuristics,
   truncation, retry or candidate-conditioned obligation deletion.
3. **Fresh live verification.** Freeze corrected labels and independent
   countercontrols before a new bounded diagnostic. Preserve failures and report
   both faithful acceptance and defect detection. Offline parser tests cannot
   prove that the model obeys the new semantic instructions. No reuse of the
   spent 64-call pilot authority and no reinterpretation of its old responses
   as new-version evidence.

Only `benchmarks/digest_retention_inventory.py` changes among the 512 pinned
pre-existing Python/SQL files. Runtime code, deployed processes, stores and the
earlier failed confirmation are untouched. This is an offline candidate and
test-contract repair, not LME readiness or deployment authorization.

## Scope limitations

These controls are manually supplied retention candidates, not proof that the
producer would generate each toy procedure. Some old source domains are outside
the technical-task producer policy; new copies preserve those sources for a
controlled regression comparison. Fresh technical-domain controls are needed
for broader production relevance. No finite set establishes fault-free model
behavior, exhaustive semantic completeness, or full benchmark convergence.

## Narrow v4 field-authority fix, verified offline

The live evidence exposed an enforceable code gap: the instructions deny
procedure-rule authority to retrieval triggers/entity mentions, but the parser
previously accepted them as the sole witness for a retained/altered prerequisite.
A separate agent added a deterministic guard to `_parse_matching`. For procedure
`constraints` and `ordering`, a `retained` or `altered` judgment now needs at least
one non-retrieval/non-entity witness. An invalid judgment rejects the whole reply;
no favorable-item salvage or automatic repair is introduced.

Root compared against the frozen v3 implementation: only version v4, this guard,
and the parser docstring changed. Source inventory/matching prompts, source
selection, budgets, retries, publication guards and runtime code did not change.
Explicit conditions in imperative names remain eligible, as do description and
step/tool fields. `uncertain` remains unresolved. Material-fact and non-procedure
semantics are outside this narrow guard. A mixed irrelevant assertion plus
retrieval witness can still pass structurally; the guard is **not entailment**.

Root reproduced the defect with a synthetic reply against frozen v3, then
verified rejection under v4. This is an offline regression, not rescoring the
paid v3 replies as v4 accuracy. The implementing agent supplied 93 focused tests;
root added 22 independent controls and updated the three intentionally obsolete
expectations. The final related-module regression gate passed **2,633 tests,
four unchanged pre-existing skips, zero failures/errors across 39 modules**.
All 203 watched source/test files stayed unchanged during that gate. Network
connections were denied; one socket construction was blocked before connection.
The halted audit/export utilities separately passed 47 root-run tests.

One new root test initially addressed a derived `fields` property as though it
were a dataclass constructor field; its setup was corrected to mutate the
actual nested immutable record. No implementation change or weaker rejection
was needed. Original failed-test receipts remain preserved.

## Remaining work and runtime boundary

The original empty-chunk cue/length bug was already repaired; the subsequent
smoke exposed separate digest/fact failures and was operator-stopped. It is
incorrect to describe this latest verifier experiment as evidence that the
original chunk fix regressed.

These v2–v4 changes affect an **offline diagnostic only**. The runtime still
requires a complete bounded digest and successful fidelity/format checks before
advancing its cursor; repeated failures can quarantine work, and strict LME
correctly refuses to call that healthy convergence. No current experiment has
validated that entire path end-to-end. No production deployment or restart was
performed here, and v4 has not received a fresh live semantic evaluation.

Open failures are materiality selection, contradictory component judgments,
unsupported obligation strengthening, and unverified workload-level reliability.
Another prompt-only pass, higher retries, or loosening convergence would not
establish their resolution. Any new architecture experiment must retain these
controls, separate exact field authority from semantic evidence, measure false
acceptance as well as false vetoes, and pass untouched confirmation plus a full
original-Q1 smoke before LME clearance. Candidate reuse across dreams is a
separately versioned cost hypothesis, not a demonstrated correctness fix.
