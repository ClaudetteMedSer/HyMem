## Next decision: separate summary health from item-index completion

Read-only tracing of the frozen source identifies an intentional all-or-nothing
contract. Exact source coverage is materialized independently in
`hymem/dreaming/runner.py:1237`, but `digest.py:1041` rejects a complete primary
object if its summary exceeds the cap. A failed repair at `digest.py:763`
returns no item/source-cursor authority; `runner.py:1681` records a digest failure
and excludes it from staging. Retry/quarantine therefore prevents convergence
at `benchmarks/strictness.py:1428`, called by the LME adapter at line 1353.

This is not safely fixed by suppressing a failure counter. The current completed
digest cursor must equal the automatic-summary cursor (`digest.py:1256`), and
both staging validation and the database schema require a non-null bounded
summary. Summary text is not canonical evidence authority, but it provides
rolling generation context and Honcho session context. A legacy summary may
also contain the only surviving representation of already-pruned history
(`runner.py:1614`); it must never be discarded as an "optional" artifact.

The proposed next architecture is explicitly versioned separate state for:

1. Source-backed item indexing, retaining existing citation, coverage, shape,
   atomicity and publication checks.
2. Bounded summary generation, with its own coverage frontier, generation,
   retry state and explicit current/stale/capacity-failure status.

Only fully validated items could publish independently. A failed summary would
retain the last accepted text at its actual old frontier, plus a durable backlog
for missed source ranges. Corruption, malformed items, invalid citations and
publication failures remain fatal. Migration, staging, status/doctor, portability,
read-side behavior and generation identity must be tested together; stale summary
context must not silently be advertised as current.

A new benchmark protocol could then report "item index complete; summary
degraded" and score the actual retrieval effects, retaining all question IDs,
denominators, costs and degradation metadata. It must not be labeled a pass of
the old fully healthy indexing contract. This is a substantive contract change:
the user must decide whether summary degradation may stop aborting an otherwise
source-backed index. **That redesign has not been implemented or deployed.**
