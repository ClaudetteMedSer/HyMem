# Bounded-summary verifier: model-only development comparison

## Why this test

The [bounded-summary pilot](2026-09-18-bounded-summary-live.md) completed safely,
but both verifier arms made semantic errors. Earlier isolated-request,
evidence-ledger and reasoning-mode experiments also failed quality gates; merely
adding another prompt paragraph or retry is not an evidenced fix. Test one
different service model before changing runtime again. No model is presumed
better and no model response constitutes independent semantic proof.

The user authorized necessary DeepSeek API testing and continued this work.
This fresh scope is root-derived: **32 completions / 32 HTTP attempts maximum**,
no retries, rerolls or resume. The completed 60-call campaign is immutable and
its authority is spent. No production memory, service changes, deployment,
runtime default changes, full LME or benchmark-score claim is included.

### Decision

Do not promote Pro or claim the opt-in bounded treatment is LME-ready. The
comparison does not support fixing convergence by merely changing the model.
Nor does it justify ignoring semantic vetoes, accepting an unrelated veto as
defect detection, deleting difficult controls, or retrying until a pass occurs.
The original-Q1 end-to-end smoke and full canonical baseline remain unrun.

The next model-calibration option is an independently bounded verifier test
outside DeepSeek on the same benchmark-only inputs. That requires a provider
choice and authorization for the new destination; none is assumed here. A
further source-provenance/summary representation redesign is another research
option, not an already-proven fix. Production settings and default legacy
contracts remain unchanged pending a demonstrated candidate.
