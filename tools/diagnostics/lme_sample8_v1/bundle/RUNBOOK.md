# Fixed stock sample-eight verification v1

This separately sealed diagnostic uses the unchanged frozen R5 application.
Old Q1 bundles, paid artifacts, checkpoints and stores remain untouched.

Recipe: sample eight, seed zero, workers one, full original 500-question S
dataset; same model, endpoint, thinking, extraction canary, indexing and judge
settings as the successful Q1. The fixed selection precedes metadata inspection.
No rerolls, resumes, skipped gates, altered prompts or edited result files.

Run preflight with network none and no credentials. Validate its zero-call
real-SDK producer binding and stock CLI checkpoint cleanup before launching the
separate live container. The live worker uses only the scoped server-side key
mount and benchmark text. It does not mount production memory or the Docker
socket. Source/package/data are read-only, results are a fresh private directory.

Outer supervision is nine hours; stock indexing is at most one hour and 100
cycles per question. There is no global stock paid-call cap. Report actual
usage including the separately metered canary; unknown costs stay unknown.
Ordinary per-question failures remain failed rows; stock may continue to other
questions. Unsafe structural/cleanup exceptions halt. Do not claim immediate
accounting-error abort: the independent postvalidator refuses clean completion
when accounting is incomplete or inconsistent.

Run the corrected multi-row postvalidator in a separate network-disabled,
credential-free container with all evidence mounted read-only. It validates the
genuine archive and actual physical checkpoint, including stock reconciliation
of raw rows and every one-attempt history. Wrong answers are valid performance
outcomes; summary degradation is explicit, not counted as fully healthy output.
Both remain separate from item-indexing and process correctness.

This is not a full-500 score, category-balanced sample, live BEAM/LoCoMo pass or
production deployment. Only bounded metadata leaves Afrodite; private logs and
benchmark text stay there. Completed executions are never restarted.
